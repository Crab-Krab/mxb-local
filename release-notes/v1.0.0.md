## MXB Local for Windows

An independent personal fork of [Frostn1/mxb-app](https://github.com/Frostn1/mxb-app), based on v0.20.6. The upstream MIT license and attribution are retained.

### Install or update

Download **MXB.Local_1.0.0_x64-setup.exe** below, close MXB Local, then run it. It installs over 0.20.6-local.5 and earlier MXB Local versions, and your settings are retained. GitHub's automatic Source code downloads contain the source, not the Windows installer.

### Why 1.0.0

MXB Local now has its own version numbers. Earlier releases were numbered after the upstream version they started from (0.20.6-local.1 to local.5). With the audit work, FrostMod removed and fixes rebuilt from later upstream releases, that number no longer described what was inside. 1.0.0 follows 0.20.6-local.5 directly. The fork is still based on MXB App v0.20.6 by Frostn1.

### What's new in 1.0.0

**Fixes from MXB App v0.20.7 to v0.20.11**

Upstream has not published the source code for these releases, so these fixes were rewritten for MXB Local from upstream's release notes.

- A numbered track no longer counts as installed for its predecessor. With only "Walnut 2" installed, the post for "Walnut" or "Walnut 1" showed as installed, and its Uninstall button could remove Walnut 2. Matching servers to tracks follows the same rule.
- Tracks whose settings file writes whole numbers with a decimal point (for example `1025.0`) now load.
- **Restore all** no longer deletes files it did not restore. Before, it removed the whole folder of disabled mods afterwards. Now it only removes folders that are empty.
- A model swap that stops partway through a move no longer deletes the only complete copy of the files.
- Mods whose download has a preview picture or PDF beside the mod folder now install where the game loads them. A tyre set packed as a bare `tyres` folder lands in the right place, and an unpacked track keeps its own folder name.
- Less lag while installing. Scanning your installed mods no longer holds up the app's window, and progress updates at most ten times a second.

**Fixes from user reports**

- Star ratings show on every mod that has them. Before, ratings that arrived after the list changed (a refreshed page, Load more, a new sort) were thrown away and never asked for again. Older popular mods such as Farm14 showed no stars.
- The **Beginner**, **Intermediate** and **Pro** track filters work again. mxb-mods.com moved track difficulty to its own pages, and MXB Local now reads them. Under these filters the only order is Newest, because that is how the site lists them, and a search covers all tracks.
- During a search, the sort menu no longer offers Popular, which it showed before without applying it.

### How it was checked

Every build runs all checks: about 1,900 Rust tests, the frontend unit tests, typecheck, lint and two browser test suites, plus the Visual C++ runtime import check. New tests cover each fix above. The difficulty reader was also checked against saved copies of the site's Beginner and Pro pages.

Not tested by hand: installing on a freshly installed Windows PC, and the settings recovery on a real profile.

The attached **SECURITY-REVIEW.md** explains the remaining advisory findings and which APIs and platforms they concern. A completed scan is not a zero-vulnerability certification.

### Limits

- Unsigned personal build, not an official Frost/mxbsecure release. Automated checks do not guarantee the absence of vulnerabilities.
- Popularity covers the site's top 100 overall, narrowed to the selected category. Newest and Oldest browse the full category. Track difficulty filters list newest first only.
- Private upstream integrations and some store, geometry and server features are unavailable. Optional online features still depend on their services.
- Features added in upstream v0.20.7 to v0.20.11 that depend on upstream's private code or FrostMod are not included.
- Updates are installed manually from this fork.
